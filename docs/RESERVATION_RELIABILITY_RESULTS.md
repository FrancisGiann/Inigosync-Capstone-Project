## Owner court editor redesign follow-up

The owner page no longer presents a global physical-resource console. Rates, billing basis, pricing tier, and bookable status are managed on each court unit inside that sport's Edit view. Availability choices are shown as the other sport/unit names. For a larger court covering several smaller courts, each smaller court remains a separate selectable space; the larger court is the place to manage those capacity links. Smaller units cannot accidentally join a sibling's space, and links owned by a multi-space court stay read-only from the smaller court's editor. New units receive a dedicated availability space and update the listing count and photo-slot state before the open listing can be saved.

Independent QA initially found unsafe sibling-link options, an unlocked host-owned checkbox after rate saves, stale count/photo state after adding a unit, repeated suggested labels, and success messages for zero-row writes. These were fixed and covered by the refreshed owner fixture. The final `tests/reservation-qa-ui.cjs` run passed for owner rates/availability/add-unit flow, customer and staff booking flows, shared-resource overlap handling, and the 320–1440px layout. Static security review found no new authorization bypass: writes still rely on existing RLS, and admin inventory changes require a returned row. This fixture suite mocks Supabase; it does not replace the live overlap/race evidence above. Photo aspect-ratio/quality work remains a later follow-up, and the Pickleball unit rate split remains unconfigured pending the manager's confirmation.
